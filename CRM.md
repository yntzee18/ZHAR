# Подключение бани ЖАР к CRM

Форма бронирования собирает бронь и отправляет её одним JSON-запросом на адрес, который вы укажете. Код сайта под конкретную CRM менять не нужно. Подключение делается через сервис-посредник или свою серверную функцию.

```
Гость → форма брони → POST JSON → посредник (Albato / ApiX-Drive / Make) → CRM или система записи
                     ↑
       занятые часы ← JSON из вашей CRM (необязательно)
```

## Что понадобится

- Хостинг и домен для сайта. На ссылке claude.ai форма не может отправлять данные наружу.
- CRM или система онлайн-записи: YCLIENTS, Битрикс24, amoCRM или любая другая, с которой работает посредник.
- Аккаунт в сервисе-посреднике или своя серверная функция, например в Yandex Cloud Functions.
- Заполненные шаблоны `privacy.html` (политика) и `consent.html` (согласие) из этой папки. Подробнее в разделе «Юридические документы».

## Настройка за 5 шагов

1. **Создайте приёмник брони в посреднике.** В Albato, ApiX-Drive или Make создайте связку, которая запускается от входящего вебхука. Сервис выдаст адрес вида `https://…`.
2. **Вставьте адрес в сайт.** Откройте `index.html`, найдите в начале `<script>` блок `CONFIG` и заполните поля:
   ```js
   webhookUrl: 'https://адрес-из-посредника',
   policyUrl: 'privacy.html',
   consentUrl: 'consent.html',
   ```
3. **Отправьте тестовую бронь,** чтобы посредник увидел структуру данных.
4. **Сопоставьте поля.** Укажите в посреднике, какое поле брони куда класть. Типичная схема:
   - `customer.name` и `customer.phone` → клиент;
   - `booking.start_at` и `booking.end_at` → время записи;
   - `booking.guests` и `booking.extras` → комментарий или услуги записи;
   - `totals.total` → сумма;
   - `booking_id` → внешний номер.
5. **Проверьте живую бронь** с сайта на хостинге и убедитесь, что она появилась в CRM.

Если посредник не принимает запросы с сайта (ошибка CORS), поставьте в `CONFIG` значение `transport: 'beacon'`. Запрос будет уходить в любом случае, но сайт перестанет видеть, дошёл ли он, и не сможет предложить повтор при сбое.

## Занятые часы из CRM

По умолчанию сайт показывает условную занятость, чтобы демо выглядело живым. Чтобы зачёркнутые часы совпадали с реальным расписанием, укажите в `CONFIG` адрес JSON с занятыми часами:

```js
busyUrl: 'https://адрес-вашей-функции/busy',
```

Формат ответа: дата вечера и список занятых часов начала.

```json
{
  "2026-09-28": [18, 19, 20],
  "2026-09-29": [12, 13, 22, 23, 24, 25]
}
```

- Часы после полуночи пишутся как 24 и 25: это 00:00 и 01:00 той же банной ночи.
- Дни, которых нет в ответе, считаются полностью свободными.
- Адрес должен разрешать запросы с вашего сайта (заголовок `Access-Control-Allow-Origin`).

Такой JSON обычно отдаёт небольшая серверная функция, которая берёт записи из CRM через её API. Если расписание не загрузилось, сайт честно пишет об этом гостю и принимает бронь, а время подтверждает администратор.

## Блок настроек CONFIG

| Поле | Что задаёт |
| --- | --- |
| `venueName` | Название, которое уходит в CRM вместе с бронью |
| `webhookUrl` | Адрес приёмника броней. Пусто — демо-режим: бронь никуда не уходит, а гость видит её данные |
| `transport` | `'fetch'` (по умолчанию, видит ошибки) или `'beacon'` (для приёмников без CORS) |
| `timeoutMs` | Сколько ждать ответа приёмника, в миллисекундах |
| `busyUrl` | Адрес JSON с занятыми часами. Пусто — демо-занятость |
| `policyUrl`, `consentUrl` | Ссылки на политику и согласие. Появляются рядом с галочкой согласия и в подвале |
| `booking.open`, `booking.close` | Часы работы. `close: 26` означает 02:00 следующего дня |
| `booking.minHours`, `booking.maxHours` | Минимальная и максимальная длительность брони |
| `booking.rateDay`, `booking.rateEvening`, `booking.eveningFrom`, `booking.eveningDays` | Тарифы за час и когда действует вечерний тариф |
| `booking.guestsIncluded`, `booking.maxGuests`, `booking.extraGuest` | Сколько гостей входит в цену, максимум гостей и доплата за каждого сверх нормы в час |
| `booking.daysAhead` | На сколько дней вперёд можно бронировать |
| `booking.extras` | Дополнительные услуги: `id`, название, цена |

Цены в разделе «Цены» на странице написаны текстом. Если меняете тарифы в `CONFIG`, поправьте и их.

## Что приходит в CRM

Пример брони:

```json
{
  "event": "booking.created",
  "booking_id": "ZH-260928-K4TQ",
  "created_at": "2026-09-27T12:41:05.118Z",
  "venue": "Баня ЖАР",
  "currency": "RUB",
  "customer": { "name": "Олег", "phone": "+79265550011" },
  "booking": {
    "date": "2026-09-28",
    "weekday": "понедельник",
    "start": "15:00",
    "end": "18:00",
    "start_at": "2026-09-28T15:00",
    "end_at": "2026-09-28T18:00",
    "hours": 3,
    "guests": 5,
    "extras": [{ "id": "oak", "name": "Дубовый веник", "price": 600 }]
  },
  "price_lines": [
    { "name": "Баня, 2 ч × 3 000 ₽", "amount": 6000 },
    { "name": "Баня, 1 ч × 4 500 ₽", "amount": 4500 },
    { "name": "Гости сверх 4: 1 × 3 ч", "amount": 1500 },
    { "name": "Дубовый веник", "amount": 600 }
  ],
  "totals": { "total": 12600 },
  "consent": {
    "personal_data": true,
    "consent_url": "https://zhar-banya.ru/consent.html",
    "policy_url": "https://zhar-banya.ru/privacy.html",
    "accepted_at": "2026-09-27T12:41:05.118Z"
  },
  "source": {
    "page": "https://zhar-banya.ru/",
    "referrer": "https://yandex.ru/",
    "utm": { "utm_source": "yandex", "utm_campaign": "banya_weekend" }
  }
}
```

Пояснения к полям:

- **`booking_id`** создаётся один раз на бронь и не меняется при повторной отправке после сбоя. Используйте его в CRM как внешний номер, чтобы отсеивать дубли.
- **`booking.date`** — это дата банного вечера.
  - Для записи в календарь берите `start_at` и `end_at`: это точные дата и время по местному часовому поясу.
  - Если бронь заканчивается после полуночи, `end_at` уже следующей датой.
- **`customer.phone`** всегда в формате `+7XXXXXXXXXX`.
- **Суммы** в рублях, целыми числами. `price_lines` показывают, из чего сложилась сумма. Если бронь захватывает 17:00 в будни, часы по разным тарифам идут разными строками.
- **`source.utm`** — рекламные метки из ссылки, по которой гость пришёл на сайт. Сохраняются на всё время визита.

## Юридические документы

В папке два шаблона, подготовленных под эту форму бронирования:

- `privacy.html` — политика обработки персональных данных;
- `consent.html` — согласие на обработку персональных данных. С 1 сентября 2025 года согласие оформляется отдельным документом.

Как их использовать:

1. Заполните всё, что выделено жёлтым: юрлицо, ИНН, контакты, CRM, сроки хранения.
2. Удалите жёлтый блок «Это шаблон» вверху страницы.
3. Покажите текст юристу: шаблон не учитывает особенности вашего бизнеса.
4. Укажите `policyUrl: 'privacy.html'` и `consentUrl: 'consent.html'` в `CONFIG`. Ссылки появятся рядом с галочкой согласия и в подвале сайта.

Сайт не обращается к сторонним серверам: шрифты встроены в `index.html`, внешних скриптов нет. Трансграничную передачу данных может добавить только то, что вы подключите сами: аналитика, зарубежный посредник или CRM.

Перед началом сбора данных владелец бани также должен подать уведомление в Роскомнадзор об обработке персональных данных. Это делает компания, не сайт.

## Для аналитики

После успешной брони сайт:

- генерирует событие `zhar:booking` на `window` с полными данными брони в `event.detail`;
- добавляет в `window.dataLayer` запись `{event: 'booking_created', booking_id, value, currency}`, если на странице подключён Google Tag Manager или Яндекс Метрика через dataLayer.

## Что уже сделано на сайте

- **Проверка полей:** выбрано время, имя не короче двух букв, телефон из 10 цифр после +7, галочка согласия.
- **Маска телефона** `+7 (XXX) XXX-XX-XX`, принимает номера с 8 и +7.
- **Цена:** считается по тарифам из `CONFIG`, с переходом на вечерний тариф и доплатой за гостей.
- **Защита от ботов:** скрытое поле-ловушка, такие заявки не отправляются.
- **Сбой отправки:** выбранное время и контакты сохраняются, гость может нажать «Забронировать» ещё раз.
- **Защита от повторной брони:** только что забронированные часы сразу становятся занятыми на странице.

## Чего сайт не делает

- **Не принимает оплату.** Оплата на месте или по ссылке от администратора. Эквайринг подключается отдельно.
- **Без `busyUrl` не знает реального расписания.** Демо-занятость условная.
- **Не проверяет данные на сервере.** Проверка идёт в браузере. Если брони принимает своя функция, стоит продублировать в ней проверку телефона, времени и суммы.
